# Model pull sources

The shared pull pipeline accepts an `organization/name` repository ID or a Hugging Face HTTPS URL:

- `https://huggingface.co/organization/name`
- `https://huggingface.co/organization/name/tree/revision`
- `https://huggingface.co/organization/name/resolve/revision/path/model.gguf`
- `https://huggingface.co/organization/name/blob/revision/path/model.gguf`

`hf.co` and `www.huggingface.co` are accepted aliases. URLs cannot contain credentials, query strings,
fragments, custom ports, or parent-directory segments. File URLs must select a GGUF file. Tree URLs
select a revision, not a subdirectory. A revision containing a slash must encode it as `%2F` in that
single URL component.

The server resolves the requested branch, tag, or commit to an immutable commit, reads the file tree
at that commit, and verifies size and SHA-256 before publication. Repository and tree sources use the
configured quantization preference. File sources select the named file exactly. A missing file fails;
the server never substitutes another quantization. Split models still require and verify their complete
shard set. Arbitrary download hosts are not accepted. Downloads use the configured repository client
origin, including when an isolated Postman simulation replaces Hugging Face.

`POST /api/pull` retains its existing `model` (or legacy `name`) payload. The library, web dashboard,
terminal client, C#, TypeScript, and Python SDKs share this server behavior. Clients preserve a requested
revision and file path instead of reducing a file URL to a repository ID.

```json
{
  "model": "https://huggingface.co/organization/name/resolve/commit/path/model.gguf",
  "stream": true
}
```

Progress is NDJSON. `downloaded` is bytes; `percent` is a fraction from zero through one. A final
`{"status":"success"}` confirms verified publication. An `error` record can arrive after HTTP headers,
so HTTP 200 alone does not establish success. Cancellation can leave resumable staging data but does
not publish an unverified model. Never automatically repeat a pull after an ambiguous network failure;
inspect the model inventory and request history first.

The local model name remains the submitted source string. Use the returned inventory name for later
chat, unload, and delete operations. Changing a mutable reference does not replace an already registered
model with that same name; delete it explicitly before pulling again.

The authoritative operation description is generated by `SharpAI.Server`; dashboard `operations.json`
provides the checked Explorer example. The root Postman collection uses `modelSource` and asserts a
final success record. URL validation and simulation contracts cover revision resolution, exact file
selection, missing files, unsafe URLs, concurrent pulls, checksums, resumable failures, and cleanup.
